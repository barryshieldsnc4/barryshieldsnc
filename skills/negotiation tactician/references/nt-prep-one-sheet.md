# The Negotiation One-Sheet — Prep Template

Use this file in Prep mode. The one-sheet is the entire preparation for a negotiation, condensed to a single page the user can glance at mid-conversation. **Always deliver it filled in for the user's actual situation — never hand back the blank template.** Interview briefly only for genuinely missing essentials (the counterpart, the ask, the money stakes); assume and state the rest.

## The seven sections

### 1. Objective
The specific, optimistic-but-defensible outcome. One sentence. "Renew at no more than a 4% increase with the SLA upgraded" — not "get a good deal." Write the *best realistic* outcome, because aiming at your minimum guarantees you drift below it.

### 2. Best case / Worst case / Walk-away
Three lines:
- **Best case:** the outcome if everything breaks right.
- **Worst acceptable case:** the least you'd still sign.
- **Walk-away line:** the explicit no-deal boundary, written as a sentence the user could say out loud. This line exists so that deadline pressure and sunk cost can't move it in the moment. No deal is better than a bad deal.

### 3. Summary (the "that's right" target)
Two or three sentences stating the *counterpart's* view of the situation — their pressures, their logic, their stakes — accurately enough that if read aloud, they'd say "that's right." Writing this before the negotiation forces the empathy work early and produces the raw material for labels and the accusation audit.

### 4. Accusation audit
The 3–5 worst things the counterpart is thinking about the user's position, converted to deliverable labels, ordered worst-first. Build per `nt-accusation-audit.md`. If no plausible negative perceptions exist, say so and skip — don't invent phantom accusations.

### 5. Calibrated questions
3–5 questions, each targeting something specific:
- One that surfaces their **real constraint** ("What's the biggest challenge on your side?")
- One that surfaces the **hidden stakeholders** ("How does this decision get made over there?")
- One that makes them **work the user's problem** ("How am I supposed to justify that internally?")
- One that tests **deadlines or alternatives** ("What happens on your end if this doesn't close this month?")
Tag each with what it's designed to extract.

### 6. Money plan (when terms are numeric)
Per `nt-bargaining.md`:
- **Target number** (precise, researched).
- **Anchor decision:** anchor first (well-informed) or let them anchor (less informed) — say which and why.
- **Ackerman ladder:** the actual four numbers (65% → 85% → 95% → 100% of target, or inverted if selling), final number odd and precise, plus the non-monetary throw-in attached to the final offer.
- **Trade list:** 2–4 non-monetary items cheap for the user but valuable to the counterpart, and vice versa.

### 7. Counterpart read
- **Probable type** (Analyst / Accommodator / Assertive) per `nt-counterpart-reading.md`, with the one pacing adjustment that implies.
- **Black swan hypotheses:** 2–3 guesses at hidden constraints or stakes, each paired with the question that would surface it.
- **Prior lessons:** anything relevant from `nt-lessons-log.md` — same counterpart, same type, same situation shape.

## Output format

Deliver as a single tight document under the heading **Negotiation One-Sheet — [counterpart / matter]**, sections in the order above, no padding. If the user asks for it as a file, produce it as markdown (or docx on request). Close with one line naming the opening move: which tactic starts the conversation and why.
